# DataClaw 演示与讲解脚本

> 用途：5 分钟产品演示 / 面试作品讲解 / 客户 POC 走查。所有步骤对应真实可点界面与真实数据，不需要任何预录视频。
> 启动：`scripts\run.cmd` → http://127.0.0.1:8787 ；重置数据：`scripts\seed.cmd --reset`

---

## 一、5 分钟演示时间轴

| 时间 | 做什么 | 说什么（一句话卖点） |
|---|---|---|
| 0:00–0:20 | `admin` 登录 → 落在「运营总览」 | "这是企业侧的统一视图：5 个数字员工、多少会话、多少次工具调用、**4 次越权被拦截**。企业买不买，先看的是这一排。" |
| 0:20–0:50 | 点「员工」→ 点一个员工看右栏（SOUL / 技能 / 记忆） | "数字员工 = 角色模板 + SOUL 设定 + 技能 + 记忆。不是聊天机器人，是有岗位职责的。" |
| 0:50–1:20 | 点「技能超市」→ 打开一个 SKILL.md | "所有能力以 SKILL.md 沉淀，**没装技能 = 运行时根本没有这个工具**，不是靠提示词约束。用户上传的技能要过静态扫描 + 管理员审核。" |
| 1:20–2:40 | 换 `analyst` 登录 → 点员工 → 点「工时效率分析」 | "一句话：它自己找表、生成 SQL、**过数据权限网关**（薪资列已脱敏），然后出大屏 + 2900 字报告。以前这条链路要 2-4 周。"（展开步骤时间线，点开 SQL 看改写前后） |
| 2:40–3:20 | 换 `sales` → 「拜访前准备」 | "它调 CRM，但**只能看到自己负责的 12 家客户**——行级过滤在 SQL 层注入，不是前端过滤。客户名说错它会自动回退并明示。" |
| 3:20–4:40 | 换 `legal` → 「审查合同」→ **先停住审批弹窗** | "这里是关键：导出含企业条款的修订版属于高风险动作，**流会挂起等人批**。拒绝就跳过并说明；批准后产出带 Word 修订痕迹的 docx。"（批完点下载，用 Word 打开给客户看修订痕迹） |
| 4:40–5:00 | 回 `admin` → 「数据安全」→ 生效矩阵 / SQL 改写预览 → 「审计日志」 | "最后回答企业最关心的两问：**他为什么看不到？**（生效矩阵给出命中策略与原因）**出了事查得到吗？**（审计里每条 SQL 都有改写前后、脱敏列、耗时与结果）" |

**演示中必须点开的三个"证据位"**（否则看起来像 PPT）：
1. 大屏产物的「数据来源」折叠 → 改写前后 SQL + `maskedColumns: salary`。
2. 合同产物的「下载修订版」→ 用 Word 打开看 `w:ins/w:del` 修订痕迹。
3. 审计详情 → 一条 `result=denied` 的越权记录 + 一条 `hitl_approval`。

## 二、10 个可讲的架构决策（每个都能被追问）

| # | 决策 | 一句话理由 | 证据/位置 |
|---|---|---|---|
| 1 | 不 fork Dify/FastGPT | 许可证禁止多租户运营与去 LOGO，且社区版运行时自认不是安全边界 | `docs/02` §0.2 前提二 |
| 2 | 数据权限自研（sqlglot AST 网关） | Ranger 管不到业务库即席查询、Sentry 已归档、ShardingSphere 只做列脱敏 | `services/sqlguard.py`、`docs/02` §E |
| 3 | 权限求值「用户级优先于角色级」 | 否则角色兜底 deny 会覆盖用户级 allow（实测踩过的 P0） | `services/policy_service.py`、`docs/04` §7 |
| 4 | 技能即能力（toolNames → 运行时注册） | 能力边界在装载层，不在提示词层；没装就是没有 | `runtime/registry.py` + `seed/skills_data.py` |
| 5 | HITL 在流式管道里挂起等待 | 高风险动作不能"先做完再说"；审批可超时自动取消并落审计 | `runtime/approvals.py`、`api/sessions.py` |
| 6 | 产物由工具生成，不让 LLM 自由发挥 | 图表数字来自真实结果集；报告引用真数；docx 可回读校验 | `tools/{chatbi,dashboard,report,contract}.py` |
| 7 | 离线 Planner + 可切换 LLM Provider | 无 Key 也能演示；有 Key 走 function-calling，工具层完全复用 | `runtime/planner.py`、`runtime/llm.py` |
| 8 | 沙箱做成 Provider 接口 | V1 本地工作空间（配额 + 路径穿越防护），V2 换 Docker/OpenSandbox 不动上层 | `runtime/sandbox.py` |
| 9 | 公共员工 = 定义 + 版本 + 下发副本 | 企业的"公共能力"，用户的"个人记忆"，两者不打架 | `services/assignment_service.py` |
| 10 | 审计是产品功能不是日志 | 含 denied、含改写前后 SQL、可按人/动作/风险/时间筛，能回答合规问题 | `api/audit.py`、`models.AuditEvent` |

## 三、常被追问的 8 个问题（备好答案）

1. **"和 Dify/Coze 有什么区别？"**
   它们卖编排与 RAG；我们卖**企业数据面 + 员工资产化 + 中国 IM + 结算审计**。我们的数据权限是 SQL 层强制的，它们的可视化编排给不了这个。
2. **"LLM 幻觉乱写 SQL 怎么办？"**
   三道闸：SQL 只读白名单（DML/DDL 直接拒）、AST 级权限改写、LIMIT 收敛；报表里的数字都来自结果集，且产物里保留改写前后 SQL 供核对。
3. **"权限绕过怎么防？"**
   员工本身没有权限，一切以**会话用户**求值；工具只能在运行时注册且必须过 policy；每次 denied 都写审计（演示里 4 条）。越权不是"报错"，是**策略层拒绝 + 可读原因**。
4. **"沙箱隔离到什么程度？"**
   当前是进程内工作空间级（每员工独立目录 + 配额 + 路径穿越防护），Provider 已抽象，生产切容器（OpenSandbox/Firecracker）。**这点如实说，不要吹**。
5. **"合同审查能替代法务吗？"**
   不能。它做的是**初审提效**：12 类规则逐条评估、风险分级、给修订建议，最终必须人审（HITL）。演示里高 5 / 中 4 / 低 2 就是给人排序用的。
6. **"检索为什么不用向量？"**
   V1 用 BM25（中文 2-gram）足够跑通"知识中台 + ACL"，向量与 rerank 是 V2；接口已按 `search(query, topK)` 抽象。
7. **"多租户/计费呢？"**
   V1 单租户私有化（企业主流形态），`tenant_id` 字段已预留；计费与配额在 V1.2。
8. **"这套东西你自己多久做出来的？"**
   调研 + 报告 + 全栈原型是一个工作日内完成的（22 个并行子任务协作）；核心难点不在写页面，在**权限网关、产物可验证、HITL** 这三件事。

## 四、雷区（演示时不要说的话）

- ❌ "我们的隔离是容器级"——V1 是工作空间级，说清楚反而加分。
- ❌ "AI 会自动改生产库"——本产品**只读 + 需审批**，这是安全卖点。
- ❌ "我们比 Dify 强"——改说"我们解决的是它不做的那四件事"。
- ❌ 承诺"合同审查可直接签"——必须是"初审 + 人审"。
- ❌ 在客户面前改数据/改代码——演示前跑一次 `scripts\seed.cmd --reset`。
