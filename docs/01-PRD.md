# DataClaw 企业级数字员工平台 — 产品需求文档（PRD）

> 来源：`DataClaw_V1.0.pdf`（汉得信息·数智事业部，2026，股票代码 300170）逐页解读 + 竞品/开源生态调研（见 `02-技术调研报告.md`）

## 1. 一句话定位

**把"个人的龙虾"变成"企业的数字员工队伍"**：一个私有化部署、内置数据能力、每人独占沙箱、权限继承自员工账号的 AI Agent 平台。业务用户说一句话，数字员工自己规划、调工具、查数据、出交付物（大屏/报告/拜访指南/修订版合同）。

- 个人版 OpenClaw（龙虾）：能力全开、野生、极客向 —— **有价值，但企业不敢用**。
- DataClaw（灵舟）：在保留"能自己干"的前提下，补齐企业必需的 **安全、落地、沉淀、管理** 四件事。

> **口径修正（据 02 调研报告 §0.2）**：截至 2026-10，OpenClaw 已出现团队版能力（operator 角色、共享会话、沙箱、ClawHub 扫描），PDF 第 3 页"个人版无隔离、无管理"的对比已部分过时。对客话术应改打 **企业数据面（行列级权限 / 脱敏 / 审计）、中国 IM 渠道、员工与技能资产化、统一结算** 这四点——这也是本实现的重心。

## 2. 目标用户与角色

| 角色 | 典型人 | 诉求 | 平台对应 |
|---|---|---|---|
| 业务用户（member） | 数据分析师、销售、法务、运营 | 不想等排期、不想学 SQL/工具，要"说完就有结果" | 工作台：会话、我的员工、技能超市、文件 |
| 部门管理员（dept_admin） | 数据组/销售部负责人 | 管好本部门的员工与权限，沉淀部门资产 | 本部门公共员工、本部门数据权限、本部门审计 |
| 平台管理员（platform_admin） | 数智事业部/IT | 统一管控：用户、公共员工、技能审核、数据权限、渠道、审计 | 管理后台全量 |
| 决策者 | CIO/业务 VP | 投入产出、风险可控、可复制 | 运营总览：员工数、会话量、工具调用、越权拦截、风险分布 |

## 3. 核心痛点 → 产品能力（PDF「四座大山」的解法）

| 企业痛点（PDF 第 4 页） | 具体表现 | DataClaw 能力 | 本仓库落点 |
|---|---|---|---|
| **安全不可控** | 技能包藏恶意代码、API Key 明文、数据外传无追溯 | 私有化部署、容器/工作空间隔离、技能静态扫描 + 审核上架、凭据不落前端、全链路审计（含 denied） | `runtime/sandbox.py`、`skills.scan`、`audit_events`、`audit.py` |
| **落地难** | 装不上、配不好、连不上 OA/CRM | 平台化开箱即用（无需安装客户端）、模板一键建员工、内置技能、数据源/知识库接入、IM 渠道 | `templates`、`employees`、`skills(12)`、`datasources`、`channels` |
| **沉淀难** | 个人经验随人走 | 技能资产化（SKILL.md 可复用）、公共员工统一定义与版本下发、员工级记忆、产物归档 | `skills`、`public_agents`+`assignments`、`memories`、`artifacts` |
| **管理难** | 无法统一管、多个 AI 不协作、越权无审计 | 统一 AI 员工管理、公共员工池一键分配、权限继承绑定用户、Agent 操作全链路审计 | `public_agents`、`policy_service`、`audit.py` |

## 5. 三个标杆场景（产品验收的"三把尺子"）

### 5.1 场景一：工时分析（2-4 周 → 5 分钟）
**Before**：业务口头提需 → 数据团队排期（1-3 周）→ SQL+ETL+看板开发 → 交付后"不是我要的" → 返工。
**After**：业务说"帮我分析下上季度各区域工时效率情况" → 数字员工：
1. 识别可用数据集（`worktime_fact` 等）与字段，说明口径；
2. 生成聚合 SQL 并**经过数据权限网关**（行级过滤 + 敏感列脱敏）后执行；
3. 产出**可视化大屏**：区域×月工时热力图、区域对比柱状图（异常标红）、月度趋势线、部门占比；
4. 产出**深度报告**：结论先行 → 数据明细 → 归因（加班集中/交付下降）→ 建议，≥1200 字；
5. 沉淀：分析逻辑写回技能与记忆，下次直接复用。
**验收**：KPI ≥3、图表 ≥3、洞察 ≥3（含 1 条异常预警）、SQL 可在产物中看到"改写前后"、薪资列显示"已脱敏"。

### 5.2 场景二：销售情报（2-3 小时 → 2 分钟）
**Before**：销售登录 CRM 查订单/沟通/合同 → 搜官网/新闻/财报/工商 → 手工拼装 → Word 写话术。
**After**：销售说"我要拜访 XX 客户" → 数字员工调 CRM（受行级权限：只能看自己名下客户）+ 外部公开信息（模拟）+ 知识库方法论 → 产出结构化拜访指南：客户 360、潜在需求预判、沟通策略、话术要点（3 段）。
**验收**：客户画像字段 ≥6、历史订单/沟通记录真实来自库、话术 ≥3 段、可复制。

### 5.3 场景三：合同审查（4-8 小时 → 10 分钟）
**Before**：法务逐页通读 → 跨页比对 → 逐条批注 → 手写修订意见。
**After**：上传合同说"按公司标准合同规则审查" → 数字员工解析（PDF/Word/扫描件）→ 匹配企业审查规则库（12 条规则）→ 风险分级（高/中/低）+ 逐条修订建议 → **HITL 审批** → 输出**带修订痕迹的 docx**。
**验收**：风险项 ≥6、分级正确、docx 可被 Word 打开、修订痕迹可见、审批记录入审计。

## 6. 非功能需求

| 维度 | 要求 | 本仓库实现 |
|---|---|---|
| 安全 | 私有化、数据不出域、最小权限、越权可拦截可追溯 | 本地部署；工作空间隔离；SQL 网关；审计 |
| 权限 | 员工无独立权限，一切以"会话用户"身份求值 | `policy_service` + `runner` 携带用户上下文 |
| 性能 | 首字延迟 < 3s；单轮工具链 < 60s；大屏 5 分钟内 | 离线 Planner 本地执行，无网络依赖 |
| 可用 | 无 LLM Key 也能演示（工具链真实执行） | `OfflinePlanner` + Provider 可切换 |
| 可观测 | 每次工具调用/SQL/审批可回放 | `tool_calls` + `messages.steps` + `audit_events` |
| 可移植 | SQLite → PostgreSQL；本地文件 → 对象存储 | SQLAlchemy 方言无关 + 路径抽象 |
| 合规 | 敏感分级、脱敏、审计留痕 | 4 级敏感度 + 4 种脱敏 + 审计 |

## 7. 指标（产品成功后看什么）

- **采用**：周活业务用户数、人均会话数、员工创建数、技能安装数。
- **交付**：单场景交付时长（目标：大屏 <5min、拜访指南 <2min、合同审查 <10min）、产物下载率。
- **安全**：越权拦截次数、高风险审批通过率、敏感列访问次数、技能审核通过率。
- **沉淀**：用户级技能数、公共员工复用人数、记忆命中率。
