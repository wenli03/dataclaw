# DataClaw 精简实现（Go 单二进制）

> 同一产品的第二份实现：**Go + 原生 Web（无前端框架/无构建链）+ 单文件 SQLite**。
> 目标：功能覆盖 PDF 里的三条标杆场景与企业管控能力，代码量压到参考实现的 **1/9**。
> 目录：`lean/`（可与 `backend/` + `frontend/` 的 v1.0 参考实现并存）

---

## 1. 结论

| 指标 | v1.0 参考实现 | v1.1 精简实现 | 变化 |
|---|---|---|---|
| 代码行数（不含依赖） | **30,998**（Python 17,878 + TS/TSX 13,120） | **3,488**（Go 2,625 + HTML/JS/CSS 863） | **−88.7%** |
| 源文件数 | 91 | 16 | −82% |
| 运行时依赖 | Python 3.11 + Node 18 + pnpm + 12 个 pip 包 + 6 个 npm 包 | **1 个静态二进制**（Go 运行时 + SQLite 驱动 + ECharts 内嵌） | 免安装 |
| 启动方式 | 3 步（pip install / pnpm build / uvicorn） | **双击 `dataclaw.exe`** | 0 构建 |
| 构建产物 | 前端 1.6MB 静态 + Python 源码 | 17MB 单 exe | 单文件分发 |
| 首屏链路 | React SPA → 20+ 次 API | 2 次（`/api/bootstrap` 一次拿全 + 静态资源） | 少 90% 往返 |
| 单轮对话耗时 | ~150ms（工具链） | **~100ms** | — |
| 自动化测试 | 23 个（pytest） | **5 个 Go test**（覆盖网关/规则/大屏/检索） | 用例更少但覆盖核心 |
| 页面数 | 2 个壳 + 12 个页面 | 3 个 HTML 壳 + 5 个 Tab | — |
| API 操作数 | 78 | **19** | −76% |

> "代码量"统计口径：只算仓库内自己写的文件；`echarts.min.js`（第三方）与 Go 依赖不计入。

## 2. 靠什么砍掉 89% 的代码

| # | 手段 | 砍掉的东西 | 代价 |
|---|---|---|---|
| 1 | **SSR→轻 SPA**：3 个 HTML 壳 + 服务端渲染好的产物 HTML | React 组件树、路由、状态管理、Vite/Tailwind 构建链、13 个页面组件 | 没有组件复用生态，交互复杂度有上限 |
| 2 | **单表文档存储**：`store(kind, id, json)` | 25 张表、SQLAlchemy 模型、迁移、JOIN 查询、DTO 转换 | 无强 schema/外键；统计要在内存里算（演示规模 <1000 行没问题） |
| 3 | **API 合并**：`/api/bootstrap` 一次返回工作台全部数据；管理页 `/api/admin` 一次返回 6 个面板 | 60 个细粒度 endpoint、前端 20+ 次请求 | 单次 payload 变大（~7KB），不适合超大列表 |
| 4 | **报告直接产 HTML** | Markdown 解析器、前端渲染管线 | 不能直接导出 .md（可加 10 行） |
| 5 | **词法 SQL 网关**替代 sqlglot AST | 一个 Python 依赖 + AST 树操作 | 只支持单表/简单查询；复杂 SQL 需换解析器（见 §5） |
| 6 | **只做一条主干**：员工→会话→工具→产物→审计；数据源/知识/渠道/策略压进 2 个管理页的 Tab | 独立的文件管理、任务看板、指标管理、渠道对话等 6 个模块 | 功能面收窄（但三场景与管控能力不减） |

## 3. 保留了什么（对齐 PDF）

| PDF 能力 | 精简实现 |
|---|---|
| 数字员工（模板/SOUL/技能/记忆） | 4 个角色模板、员工创建与 SOUL 编辑、技能装载（未装载=工具不注册）、记忆开关 |
| 公共员工（统一定义→分配→副本） | 2 个公共员工、一键分配给任意业务用户、副本带独立记忆 |
| 技能超市（企业级 + 用户级 + 隔离） | 6 个内置技能（SKILL.md 全文可查看）、按员工装载、装载即审计 |
| 会话即交付（流式 + 工具轨迹 + 产物） | SSE：`start/step/artifact/delta/approval/done`；步骤可展开看工具输出 |
| 三大标杆场景 | 工时大屏（5 KPI/4 图/3 洞察）+ 深度报告；拜访指南 HTML；合同 12 项风险 + 修订版 docx |
| HITL 审批 | 导出前流挂起 → 前端弹窗 → 批准/拒绝 → 继续/跳过；审批入审计 |
| 数据安全（表/列/行/脱敏/审计） | 12 条策略；行级注入、`SELECT *` 展开、4 类脱敏、SQL 改写前后对比；越权/写操作/多语句全部拒绝并审计 |
| **权限继承** | 一切以「会话用户」求值；管理员可在预览里切换身份看差异 |
| 知识中台 | 3 篇制度/方法论 + 检索（片段 + 出处 + 分数） |
| 渠道接入 | 免登录 webhook（`X-DataClaw-Token` 校验）+ 知识库应答 |
| 审计 | 每次工具/查询/导出/审批/策略变更落库，管理页可按结果筛选 |

## 5. 取舍与代价（必须说清楚）

| 取舍 | 影响 | 何时必须换回 v1.0 方案 |
|---|---|---|
| 词法 SQL 网关（非 AST） | 不支持子查询/UNION/CTE 的细粒度列解析；行过滤是 `AND` 合并，遇到 OR 语义会收紧 | 对外开放任意 SQL、或需要精确语义时 → 换 sqlglot/JSqlParser/Calcite |
| 单表 JSON 存储 | 无 schema 约束、无 JOIN、统计走内存 | 数据量 > 万行或需要复杂查询 → 换正规表结构/Postgres |
| 19 个 API | 单次响应大；列表无分页 | 大数据量/移动端弱网 → 拆细 + 分页 |
| 审批状态在进程内存 | 多 worker/多实例不共享 | 生产多副本 → Redis pub/sub 或 DB 轮询 |
| 无真实 SSO、无容器沙箱、无向量检索、无 IM 长连接 | 与 v1.0 相同的 V1 边界 | 见 `docs/03` §12 演进路径 |
| UI 手写（无组件库） | 复杂交互（拖拽/虚拟列表/富文本）成本高 | 后台功能继续膨胀 → 回 React |

**结论**：精简版适合 **演示、POC、内网小规模落地、单机私有化交付**；需要多租户、复杂编排、大规模数据的场景，用 v1.0 的分层实现并按 `docs/03` 的演进路径推进。

## 6. 运行

```bash
cd lean
go build -o dataclaw.exe .          # 首次需联网拉 Go 依赖（modernc.org/sqlite）
./dataclaw.exe -addr 127.0.0.1:8788 # 默认数据目录 ./data（自动建库+演示数据）
```
或 Windows 一键：`scripts\lean.cmd`（构建 + 启动）。

演示账号与 v1.0 相同：`admin/admin123`、`analyst|sales|legal/123456`。

重建演示数据：删除 `lean/data/` 后重启即可（seed 幂等）。
测试：`cd lean && go test ./...`。
